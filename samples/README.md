# Sample datasets

**All four files in this folder are entirely fictional.**

They were written for DataProof so that the checks can be demonstrated and tested
without touching a real dataset. They must not be used to make any claim about real
departments, candidates, elections, health statistics or expenditure figures. No
department, polling unit, candidate, region or figure here corresponds to anything in
the real world.

## Files

| File | Records | Columns | Purpose |
| --- | --- | --- | --- |
| `government-expenditure-2023.csv` | 24 | 4 | Missing values, duplicate records, a negative figure, a category written two ways, an outlier, an overspend |
| `government-expenditure-revised.csv` | 23 | 4 | A second version of the file above, for the comparison screen |
| `election-results.csv` | 23 | 5 | Duplicate polling units, two identifier formats, missing values, an inconsistent state name, a malformed row |
| `public-health.csv` | 30 | 4 | Missing values, indicator names in several cases, text in a numeric column, a negative count, a placeholder value |

## Every introduced issue, documented

See [`../docs/SAMPLE-FINDINGS.md`](../docs/SAMPLE-FINDINGS.md) for the complete list of
deliberately introduced problems and the findings DataProof actually produces for each
file. That document is generated by running the shipped checks over these exact files,
so it cannot drift out of step with the behaviour.

## How they are used

- **In the application** — the Dashboard and the Analyze screen load them from
  `src/lib/sampleData.ts`, which contains the same content as these files. Nothing is
  fetched over the network.
- **In the tests** — `src/test/samples.test.ts` asserts that each documented issue still
  produces the expected finding, which makes the documentation part of the test suite.
- **In the comparison demo** — load `government-expenditure-2023.csv` as the older file
  and `government-expenditure-revised.csv` as the newer, then match on **Department** +
  **Financial Year**.

## Keeping the files in step

`src/lib/sampleData.ts` is the source of truth. If you change a sample, regenerate
these CSV files and the findings document:

```bash
npx tsx scripts/gen-samples.ts > /dev/null   # rewrites samples/*.csv from sampleData.ts
npx tsx scripts/gen-findings.ts > docs/SAMPLE-FINDINGS.md
npm test
```
